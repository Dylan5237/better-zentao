# 08 配置说明

> 配置只承载**环境差异**（地址、ID、人员映射、阈值、日历），不承载**做法差异**。
> 团队之间做法不同时，先按 11 需求演进指南判断是否修改规范，而不是增加一个配置开关（ADR-10）。

## 1. 配置来源与优先级

| 优先级 | 来源 | 用途 |
| --- | --- | --- |
| 1（最高） | 命令行参数 | 临时覆盖，如 `--config`、`--product` |
| 2 | 环境变量 | 凭据与地址（不进文件） |
| 3 | 用户配置 `~/.better-zentao/config.json` | 个人偏好（如 `mode`、`notify.personal`） |
| 4 | 团队配置（共享目录或仓库 `config/team.json`） | 产品、模块、团队、日历、阈值 |
| 5 | 内置默认值 | `src/core/config.ts` |

- 团队配置由项目管理维护，放在共享目录或单独的配置仓库，所有人引用同一份；个人配置只能覆盖 §4 中标为"个人可改"的项。
- 启动时用 zod 校验合并结果；校验失败直接退出并打印字段路径（不打印值）。`bzt doctor` 会做同样检查。

## 2. 环境变量

运行环境为 Node 24 LTS，最低 24.11.0（ADR-17）。SQLite 随 Node 分发，实验性警告保留在 stderr。

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `ZENTAO_BASE_URL` | 是 | — | 禅道地址，如 `https://zentao.example.internal`，不带 `/api.php` |
| `ZENTAO_ACCOUNT` | 是 | — | 本人禅道账号 |
| `ZENTAO_PASSWORD` | 是 | — | 本人禅道密码。Windows 推荐用 `bzt install-agent` 写入凭据管理器，进程启动时读取 |
| `ZENTAO_TIMEOUT_MS` | 否 | `15000` | 单请求超时，单位毫秒。留空使用默认值，显式值须为 1 至 2147483647 的整数 |
| `BZT_CONFIG` | 否 | — | 团队配置文件路径 |
| `BZT_WECOM_WEBHOOK` | 否 | — | 企微群机器人地址；为空时不推送 |
| `BZT_LOG_LEVEL` | 否 | `info` | `debug` 也不会输出请求体和响应体 |
| `BZT_HOME` | 否 | `~/.better-zentao` | 本地状态目录 |

**禁止**把凭据写进配置文件、Agent 的 MCP 配置文件（`codex.config.toml` 等）或仓库。`bzt install-agent` 生成的 MCP 配置只引用环境变量或凭据管理器。

## 4. 字段说明

| 路径 | 类型 | 说明 | 个人可改 |
| --- | --- | --- | --- |
| `mode` | enum | `personal`：按 W0–W3 分级；`strict-ai`：所有写入至少 W2，`source` 默认 `ai` | 是（只能更严） |
| `timezone` | string | IANA 时区 | 否 |
| `products.<id>.state` | enum | 设计态 / 运行态 / 交付态 / 其他；决定配对与提示语 | 否 |
| `products.<id>.enabled` | bool | `false` 时只读，不推荐写入（#44 精细模式待定） | 否 |
| `products.<id>.probeOnly` | bool | 只允许 `bzt probe` 写入 | 否 |
| `modules.<pid>:<mid>` | object | 模块的设计主管、研发主管、测试负责人；角色解析（04 §2）与跨模块提需（N10）的依据 | 否 |
| `teams` | object | 团队成员与主管；`get_team_work`、`get_member_schedule` 默认范围 | 否 |
| `roles` | object | 角色权限：如发布例外只允许 `PM` 登记 | 否 |
| `aliases` | object | 自然语言称呼 → 账号 | 否 |
| `naming.*` | object | N04 命名；`legacy*` 只用于识别历史数据，不用于新建 | 否 |
| `versionTag` | object | 关键词中的版本标签格式 | 否 |
| `releaseCalendar` | array | 版本发布日；`release.read` 验证后改为以禅道发布对象为准，此处作为补充 | 否 |
| `stageDefaults` | object | 拆解默认日期与默认负责人；日期为计划性字段，可默认（05 §5.4） | 否 |
| `rules.Rxx` | object | 规则开关与阈值；P1 默认只开 R01–R05 | 否 |
| `schedule.dailyHours` | number | 每日可用工时（待确认，默认 6） | 否 |
| `calendar` | object | 工作日、节假日、调休 | 否 |
| `notify` | object | 摘要时间、事件推送、去重 | 部分（`quietHours`） |
| `wecomMap` | object | 账号 → 企微 ID | 否 |
| `write.*` | object | 写入参数 | 否 |
| `probe.productId` | literal | 仅允许数字 `29`，省略时也是 `29`。发送层固定为 #29，其他产品值会被拒绝（ADR-19） | 否 |
| `snapshot` | object | 月度快照采集人、日期、导出目录 | 否 |

## 5. 校验规则（`bzt doctor` 同步检查）

| 编号 | 检查 | 失败时 |
| --- | --- | --- |
| CFG-01 | 环境变量齐全、能登录 | 退出 |
| CFG-02 | `getconfig.version` = 22.6；`URAndSR=true` | 版本不符时警告，所有写能力降级为 `unverified` |
| CFG-03 | `products` 中的 ID 都存在 | 退出 |
| CFG-04 | `modules` 的模块 ID 属于对应产品 | 列出无效键 |
| CFG-05 | `modules`、`teams`、`roles` 中的账号都在目录中且未删除 | 列出无效账号 |
| CFG-06 | 每个启用产品的每个一级模块都能解析出研发主管（直接或兜底） | 列出缺失模块（`CONFIG_MISSING`） |
| CFG-07 | `calendar.holidays` 覆盖当年 | 警告 |
| CFG-08 | `BZT_WECOM_WEBHOOK` 可达（发送测试消息需 `--send-test`） | 警告 |
| CFG-09 | P0 骨架检查内置 SQLite 能否打开内存库并查询。P1 起检查本地状态目录可写、SQLite 版本迁移完成 | 退出 |
| CFG-10 | 配置中不含疑似凭据的字段（`password`、`token`、`secret`） | 退出 |
| CFG-11 | 执行 `bzt schedule-task install` 或 `bzt digest / snapshot` 时，当前 `ZENTAO_ACCOUNT` 必须与配置中的 `collector` 一致 | 拒绝执行并提示唯一采集账号（防群消息重复轰炸） |
| CFG-12 | `probe.productId` 若存在，必须是数字 `29` | 拒绝探查请求 |

## 6. Agent 接入配置模板

`bzt install-agent --agent codex|claude|gemini` 生成以下配置（路径以实际安装为准）：

```toml
# ~/.codex/config.toml
[mcp_servers.better-zentao]
command = "bzt"
args = ["mcp"]
env = { BZT_CONFIG = "\\\\share\\better-zentao\\team.json" }
```

```json
// Claude Code：项目根 .mcp.json 或用户级配置
{ "mcpServers": { "better-zentao": { "command": "bzt", "args": ["mcp"], "env": { "BZT_CONFIG": "\\\\share\\better-zentao\\team.json" } } } }
```

```json
// Gemini CLI：~/.gemini/settings.json
{ "mcpServers": { "better-zentao": { "command": "bzt", "args": ["mcp"], "env": { "BZT_CONFIG": "\\\\share\\better-zentao\\team.json" } } } }
```

同时复制 `skills/better-zentao/SKILL.md` 到对应 Agent 的技能目录（Claude Code `~/.claude/skills/`；Codex、Gemini 写入 `AGENTS.md` / `GEMINI.md` 的引用段落）。
