# 08 配置说明

> 配置只承载**环境差异**（地址、ID、人员映射、阈值、日历），不承载**做法差异**。
> 团队之间做法不同时，先按 11 需求演进指南判断是否修改规范，而不是增加一个配置开关（ADR-10）。

## 1. 配置来源与优先级

| 优先级 | 来源 | 用途 |
| --- | --- | --- |
| 1（最高） | 命令行参数 | 临时覆盖，如 `--config`、`--product` |
| 2 | 环境变量 | 凭据与地址（不进文件） |
| 3 | 用户配置 `<BZT_HOME>/config.json` | 个人偏好（`mode` 只能收紧，`notify.quietHours` 可覆盖） |
| 4 | 团队配置（共享目录或仓库 `config/team.json`） | 产品、模块、团队、日历、阈值 |
| 5 | 内置默认值 | `src/core/config.ts` |

- 团队配置由项目管理维护，所有人引用同一份。`--config` 优先于 `BZT_CONFIG`，两者都未设置时使用内置默认值。显式指定的团队文件必须可读且为合法 JSON。
- 用户配置可省略。`BZT_HOME` 未设置时使用 `~/.better-zentao`。无法取得非空的用户主目录时，文件配置加载跳过用户配置，完整配置加载要求显式设置 `BZT_HOME`。用户配置只允许 `mode`、`notify.quietHours` 和可选的 `$schema`。已采用 `strict-ai` 的团队禁止个人切回 `personal`。
- `--product` 指定本次命令的产品范围。只读 `bzt probe capture` 用它选择采集样本，写入探查仍固定在 #29（ADR-19）。
- 团队和个人 JSON 配置的每一层对象都要求键名唯一，转义后相同的键视为重复。重复键直接报错，只指出配置来源。随后扫描疑似凭据并用 zod 严格校验。错误路径中含已知密码或机器人密钥的字段名整体脱敏，包括短凭据。密码和企微机器人地址由调用方按需从环境读取。

## 2. 环境变量

运行环境为 Node 24 LTS，版本范围为 `>=24.11.0 <25`（ADR-17）。SQLite 随 Node 分发，实验性警告保留在 stderr。

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `ZENTAO_BASE_URL` | 是 | — | 禅道部署根地址，读取环境变量时去掉首尾空白。地址须以 `http://` 或 `https://` 开头，可带部署子目录，禁止空白、反斜杠、内嵌凭据、查询参数或片段。路径须能正确解码，其中任何完整路径段均不得为 `api.php`（忽略大小写）。配置、HTTP 客户端与探查入口使用同一校验 |
| `ZENTAO_ACCOUNT` | 是 | — | 本人禅道账号，空串或纯空白无效 |
| `ZENTAO_PASSWORD` | 是 | — | 本人禅道密码，空串或纯空白无效。由 Agent 启动环境提供，安装命令不接收或保存密码 |
| `ZENTAO_TIMEOUT_MS` | 否 | `15000` | 单请求超时，单位毫秒。留空使用默认值，显式值须为 1 至 2147483647 的整数 |
| `BZT_CONFIG` | 否 | — | 团队配置文件路径 |
| `BZT_WECOM_WEBHOOK` | 否 | — | HTTP 或 HTTPS 企微发送地址，支持内部代理域名。路径为 `/cgi-bin/webhook/send`，查询参数中须有且只有一个非空白的 `key`。禁止内嵌用户名、密码或 `#` 片段（包括空片段）。地址为空时不推送 |
| `BZT_LOG_LEVEL` | 否 | `info` | 支持 `debug`、`info`、`warn`、`error`，忽略首尾空白和大小写，未识别的值回退至 `info`。`warn` 包含 3xx、4xx 和错误级日志，`error` 记录 5xx 或状态记为 0 的传输失败，包括正文阶段超时或断连。所有级别使用同一脱敏白名单。 |
| `BZT_HOME` | 否 | `~/.better-zentao` | 本地状态目录 |
| `BZT_SERVER_CONFIG` | 否 | — | 集中部署模式（`bzt serve`，CR-008 / ADR-21）的服务端配置文件路径（`--server-config` 优先）。配置结构与安全默认值见 [server.example.json](../config/server.example.json) 与 [server-deployment.md](server-deployment.md) |

**禁止**把凭据写进配置文件、Agent 的 MCP 配置文件（`codex.config.toml` 等）或仓库。`bzt install-agent` 生成的 MCP 配置只引用环境变量或凭据管理器。

## 4. 字段说明

| 路径 | 类型 | 说明 | 个人可改 |
| --- | --- | --- | --- |
| `mode` | enum | `personal`：按 W0–W3 分级；`strict-ai`：所有写入至少 W2，`source` 默认 `ai` | 是（只能更严） |
| `timezone` | string | IANA 时区 | 否 |
| `products.<id>.state` | enum | 设计态 / 运行态 / 交付态 / 其他；决定配对与提示语 | 否 |
| `products.<id>.enabled` | bool | `false` 时只读，不推荐写入（#44 精细模式待定） | 否 |
| `products.<id>.probeOnly` | bool | 只允许 `bzt probe` 写入 | 否 |
| `modules.<pid>:<mid>` | object | 模块的设计主管、研发主管、测试负责人；角色解析（04 §2）与跨模块提需（N10）的依据。`teams` 非空时，模块填写的 `team` 须引用其中已声明的团队 | 否 |
| `teams` | object | 团队成员与主管；`get_team_work`、`get_member_schedule` 默认范围 | 否 |
| `roles` | object | 单人门户按禅道回读账号匹配 FB、PM、PJ、DM、DS、RM、RD、QA。QA_LEAD 同时拥有 QA 工作台。本机使用者可在门户勾选自己的职责并保存至团队表。其他账号按已分配职责进入。发布例外只允许 PM 登记。 | 否（门户改团队表中的本人条目） |
| `aliases` | object | 自然语言称呼 → 账号 | 否 |
| `naming.*` | object | N04 命名；`legacy*` 只用于识别历史数据，不用于新建 | 否 |
| `versionTag` | object | 关键词中的版本标签格式 | 否 |
| `releaseCalendar` | array | 版本发布日。`products` 非空时，每条记录的 `product` 须引用其中已声明的产品。`release.read` 验证后改为以禅道发布对象为准，此处作为补充 | 否 |
| `stageDefaults` | object | 拆解默认日期与默认负责人；日期为计划性字段，可默认（05 §5.4） | 否 |
| `rules.Rxx` | object | 规则开关与阈值；P1 默认只开 R01–R05 | 否 |
| `schedule.dailyHours` | number | 每日可用工时（待确认，默认 6） | 否 |
| `calendar` | object | 工作日、节假日、调休 | 否 |
| `notify` | object | 摘要时间、事件推送、去重 | 部分（`quietHours`） |
| `wecomMap` | object | 账号 → 企微 ID | 否 |
| `write.*` | object | 写入参数 | 否 |
| `probe.productId` | literal | 仅允许数字 `29`，省略时也是 `29`。发送层固定为 #29，其他产品值会被拒绝（ADR-19） | 否 |
| `snapshot` | object | 月度快照采集人、日期、导出目录 | 否 |

探查批准从签发起最长有效 60 秒（`src/core/config.ts` 的 `PROBE_APPROVAL_MAX_TTL_MS`），由发送层校验，属于固定安全上限。

## 5. 校验规则

`bzt doctor` 默认离线检查环境与配置文件。CFG-07 在加载配置后检查业务时区的当年节假日记录，缺少记录时给出警告。`bzt doctor --live` 登录禅道，通过只读接口检查实例版本、三级需求和当前登录身份，账号在输出中脱敏。命令还核对团队配置中声明的产品、模块和人员引用（CFG-03–CFG-05）。企微可达性留待后续接入。CFG-06 由调用方提供一级模块列表，CFG-11 在执行定时任务前检查。

| 编号 | 检查 | 失败时 |
| --- | --- | --- |
| CFG-01 | 环境变量齐全、禅道基础地址合法，后续检查能否登录 | 退出 |
| CFG-02 | `getconfig.version` = 22.6 且 `URAndSR=true` | 不符合时警告，所有写能力降级为 `unverified` |
| CFG-03 | `products` 中的 ID 都存在 | 退出 |
| CFG-04 | `modules` 的模块 ID 属于对应产品 | 列出无效键 |
| CFG-05 | `modules`、`moduleDefaults`、`teams`、`roles`、`aliases` 和采集账号都在活动目录中且未删除 | 列出无效账号 |
| CFG-06 | 启用产品须提供一级模块清单，已确认空清单有效。每个一级模块须有直接或兜底研发主管。仅禁用产品及标记为 `probeOnly` 的 #29 免检 | `CONFIG_MISSING`，`products` 列出缺清单的产品，`modules` 列出已知缺主管的模块 |
| CFG-07 | `calendar.holidays` 覆盖当年 | 警告 |
| CFG-08 | 非空的 `BZT_WECOM_WEBHOOK` 格式合法，后续检查可达性（发送测试消息需 `--send-test`） | 格式错误时退出，可达性失败时警告 |
| CFG-09 | P0 骨架检查内置 SQLite 能否打开内存库并查询。P1 起检查本地状态目录可写、SQLite 版本迁移完成 | 退出 |
| CFG-10 | 配置中不含疑似凭据的字段（`password`、`token`、`secret`） | 退出 |
| CFG-11 | 执行 `bzt schedule-task install` 或 `bzt digest / snapshot` 时，当前 `ZENTAO_ACCOUNT` 必须与配置中的 `collector` 一致。快照约束适用于 `capture`（含默认动作）与定时任务，允许跨机 `import/export` | 拒绝执行并提示唯一采集账号（防群消息重复轰炸） |
| CFG-12 | `probe.productId` 若存在，必须是数字 `29` | 拒绝探查请求 |
| CFG-13 | `bzt doctor` 检查当前 Node 满足 `>=24.11.0 <25` | `ok: false`，退出码 1，输出所需版本；跳过 SQLite 检查 |

`bzt` 只在组合根 `src/adapters/cli/bzt.ts` 使用 `Date.now()`，注入的墙上时钟每次调用都读取当前系统时间。其余源码通过注入获取时间。整个源码目录都禁止使用全局 `performance`。

## 6. Agent 接入配置模板

`bzt install-agent <codex|claude|gemini>` 和 `bzt install-agent --agent <codex|claude|gemini>` 均可使用。`--config <路径>` 设置 MCP 的 `BZT_CONFIG`。省略该选项时保留已有值。`--dry-run` 列出目标文件及动作。

以下配置中的团队文件路径仅为示例。三种可复制模板位于 `templates/`。

```toml
# ~/.codex/config.toml
[mcp_servers.better-zentao]
command = "bzt"
args = ["mcp"]
env = { BZT_CONFIG = "\\\\share\\better-zentao\\team.json" }
```

```json
// Claude Code：项目根 .mcp.json 或用户级配置
{ "mcpServers": { "better-zentao": { "command": "bzt", "args": ["mcp"], "env": { "BZT_CONFIG": "\\\\share\\better-zentao\\team.json" } } } }
```

```json
// Gemini CLI：~/.gemini/settings.json
{ "mcpServers": { "better-zentao": { "command": "bzt", "args": ["mcp"], "env": { "BZT_CONFIG": "\\\\share\\better-zentao\\team.json" } } } }
```

Claude Code 默认合并用户级 `~/.claude.json`。仅 Claude Code 支持 `--project <目录>`，用于指定项目根的 `.mcp.json`。三种安装均复制 `skills/better-zentao/SKILL.md` 到各自用户目录的 `skills/better-zentao/`。Codex 和 Gemini 还会合并用户级 `AGENTS.md` 或 `GEMINI.md` 中的引用段落。
