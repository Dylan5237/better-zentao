# 09 测试与验收

> 目标：让编码 Agent 可以"按测试驱动"实现，让评审人可以按用户故事验收。
> 原则：业务口径（04）用纯函数测试锁定；禅道差异（06）用真实脱敏夹具锁定；写入安全（05）用假禅道锁定；真实写入只在 #29。

## 1. 测试分层

| 层 | 目录 | 对象 | 依赖 | 运行时机 | 目标 |
| --- | --- | --- | --- | --- | --- |

### 1.1 夹具与构造器

- `test/fixtures/zentao-22.6/` 存放通过复扫的夹具。每个 JSON 文件只保存 `{ endpoint, status, body }`。文件名为 `<endpoint>.json`，实际观察到的空列表使用 `<endpoint>.empty.json`。保留状态码、结构和字段类型。账号和姓名在同一批次稳定匿名化，大型列表有界裁剪并保留代表性样本。需要比对多次采集时，各次使用独立的 `--out` 目录。
- 采集在 `src/api/internal/` 内存中完成脱敏和二次复扫，通过后才可向文件写入层交付。独立脚本 `node scripts/sanitize-fixture.ts <路径或 --stdin> [--out 文件]` 用于已有本地 JSON 或标准输入，自测覆盖 `password` 清除（S01）、复扫失败终止及安全报错。生成的 22.6 夹具保留采集命令的 JSON 格式，Prettier 仅跳过该夹具目录。
- `users` 的非空正整数键实体表仅在每项都有 `id` 时保留，并逐项脱敏。账号映射等伴随字典整段删除。账号字段中的 `closed` 保留为系统哨兵。复扫按字段区分真实身份和结构白名单，凭据始终参加复扫。模块菜单保留根路径与层级，路径片段脱敏并有界裁剪。
- 嵌套表单保留字段类型与合法枚举键，遮盖展示标签。人员下拉列表按采样上限裁剪，非哨兵账号键与同批记录使用相同的匿名账号。未知字段的非零 ISO 日期与日期时间归一为同格式示例，零日期及已识别的日期字段保留。当前用户详情保留 `profile.role.code` 中的合法角色枚举。
- WP-03 阶段 A 使用模拟响应验收 26 个只读端点、脱敏、落盘与缺口报告。阶段 B 单独授权真实只读采集，再核对入库夹具的端点覆盖。
- `test/builders/`：`aStory().feature().draft().assignedTo("acct_ds_a").build()` 风格的构造器，用于单元与服务测试，避免手写大 JSON。
- 时间一律通过 `clock.ts` 注入；测试默认"今天"为 2026-12-09（周三），日历使用 `test/fixtures/calendar.json`。

### 1.2 假禅道 `fake-zentao`

- 内存实现 06 中用到的读取端点和已验证写入端点，行为与夹具一致（包括 201 状态码、`status` 过滤失效、父子扁平）。
- 支持故障注入：`failNext("story.assign")`、`timeoutNext("story.create", { afterCommit: true })`（服务端已创建但客户端超时）、`schemaDrift("v1/stories/{id}")`。
- 记录所有写请求，便于断言"没有重复创建"。

### 1.3 覆盖率与质量门槛

| 范围 | 行覆盖 | 分支覆盖 |
| --- | --- | --- |
| `src/domain/`、`src/rules/` | ≥ 95% | ≥ 90% |
| `src/services/operation.ts`（OperationExecutor） | ≥ 95% | ≥ 90% |
| `src/api/`、`src/core/dto/` | ≥ 85% | — |
| 全局 | ≥ 80% | — |

CI 在 `windows-latest` 上分别用 Node 24.11.0 和最新 24.x 执行 `pnpm lint && pnpm typecheck && pnpm test`。`pnpm test` 先构建，再执行 `vitest run --coverage`，覆盖率低于表中适用门槛即退出失败。尚无源码的范围在加入实现后开始考核。任何规则（R01–R16）没有至少"命中 / 不命中 / 边界"三个用例时 CI 失败（`test/unit/rules/_coverage.test.ts` 检查）。

## 3. 契约测试（禅道差异）

每个坑点 Q1–Q13 对应 06 §4 中列出的测试文件，额外要求：

- 每个已使用端点至少一个"正常"夹具 + 一个"空列表"夹具。
- `ZENTAO_SCHEMA_MISMATCH`：把夹具关键字段改类型后，断言返回错误码而不是静默兼容。
- 状态码：需求列表夹具为 201，断言成功。
- 输出投影：S01 扫描所有 MCP 输出、日志和缓存。隐私字段按键名包含匹配，`ip` 按词识别以保留 `description` 等正常字段。另检查原始人员字典、认证头、会话 Cookie、带密钥的机器人地址和嵌在文本里的密码哈希。测试断言也扫描错误对象的不可枚举字段、容器条目和 Symbol 键。

## 6. 对话评测（eval）

- 每个 P1 工具至少 5 条中文表述样本（口语、简写、含角色称呼），断言路由到正确工具与关键参数。
- 补问评测：缺模块、缺验收标准、缺范围、同名人员时，Agent 必须补问而不是猜。
- 表达评测：输出必须包含口径（范围、数据时间）；`partial` 时不得给出全量结论；推测项必须标注；W2 必须先展示预览。
- 评测集位于 `test/eval/cases/*.yaml`，由 `pnpm eval --agent claude|codex|gemini` 执行，结果写入 `test/eval/report.md`。
