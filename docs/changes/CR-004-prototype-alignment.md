# CR-004 本地门户按评审原型实现

| 六步需求卡 | 约定 |
| --- | --- |
| 意图 | 使用者能沿用已评审的工作台找到自己的任务、看清进展并执行业务操作。 |
| 口径 | 以伏羲原型 `mwskyptfsv2y4a` 第 11 版（2.6.0，界面 v3.1）为界面基准，使用顶部职责标签、五个业务入口与独立的评审拍板入口，以及各角色的专属卡片。 |
| 数据 | 登录身份、职责、业务对象、进度和可用操作来自本机服务。评审议题与默认参数来自项目设计文档。 |
| 规则 | 原型可自由体验角色，真实门户只允许切换本人已分配职责。写入保留预览、确认和回执。当前服务缺少的数据明确显示缺口。 |
| 能力 | 对齐八角色首页、提需、流转与详情抽屉、拆解排期、发布风险和会议决议。保留本机启动与首次职责设置。 |
| 验收 | 分别检查桌面和窄屏布局、八角色首页、六个导航入口、权限、卡片到业务操作的实际路由，并通过同源模拟服务验证查询与写入。 |

US-QA-03 对应测试人员的发布门禁只读视图。服务端仅接受该职责的 `get_plan_progress(view=release)` 请求。例外登记沿用产品管理权限。

## 旧稿实现记录（已被伏羲第 11 版取代）

页面基准为原型工作树的 `docs/prototype/styles.css`、`views-daily.js`、`views-mgmt.js` 和 `app.js`。门户加载的 `web/prototype.css` 与该样式表经相同格式化后内容一致。顶部标签、导航、角色卡片、台账、抽屉、会议决策卡和折叠表格沿用原型结构。登录、职责设置、数据缺口及写入回执使用同一套控件。

在 Edge 的 1440 × 900 窗口下，逐页对照了八种职责首页和其余五个入口。390 像素宽度下走查了六个入口和写入回执。隔离账号完成首次选职责、切换职责、台账到进度卡、队列到拆解预览、门禁查询和需求写入恢复。写入回读失败后沿用原操作编号，测试服务只创建一次。对照截图中的数据来自隔离服务。

## 伏羲第 11 版验收基准

以正式入口 index.html 的两段样式和实际渲染结构为准。核对品牌及角色分组、六个导航入口、左侧角色卡、各职责首页三档模式、桌面一屏与卡片内滚动、命令检索、抽屉、深浅主题。按原型权限呈现可办理与只读入口。业务反馈仅显示两个入口。真实页面根据登录身份填写姓名、快照时间、记录和计数。个人排期只取自己，确认写入继续执行服务端权限、预览与回读。

使用 Edge 在同一窗口中分别渲染伏羲正式版与本机门户，输出 2000 × 934 截图。设计主管全封装首页在相同快照条件下，顶部、角色栏、侧栏、身份卡、主区、页面、页头、首张指标卡、双栏容器、待办面板、首条待办和底部提示共 12 处的位置与尺寸逐项一致。两段原版 CSS 合并格式化后与门户加载的样式表一致。

隔离账号走查覆盖八种职责的三档首页和 390 像素窄屏。关联用户需求可带入来源和标题，转发进度卡与风险详情均能打开。写入经模拟禅道完成预览、确认、刷新恢复和回读。此次验收未请求真实禅道或企微。
