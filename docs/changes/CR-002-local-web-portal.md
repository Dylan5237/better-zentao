# CR-002 单人本地 Web 门户

本次选择 ADR-20 的本机形态。一个进程监听 IPv4 回环地址，供一位使用者登录自己的禅道。P3 暂缓。

后续的 [CR-003 首次使用](CR-003-portal-onboarding.md) 增加了本机使用者在门户内维护本人职责的入口，并简化本机启动和登录。

| 六步需求卡 | 决定 |
| --- | --- |
| 意图 | 业务反馈、产品管理、项目管理、设计主管、设计人员、研发主管、研发人员和测试人员登录后直接进入各自的工作台。一人兼任多职时，可切换自己已配置的职责。 |
| 口径 | 身份取禅道当前用户接口回读的账号，精确匹配团队配置的 `roles`。沿用原有四个管理角色，新增 FB、DS、RD、QA；原有 QA_LEAD 使用测试人员工作台。无匹配时说明维护入口。主管、团队成员关系和个人姓名不自动授予角色。 |
| 数据 | 浏览器提交本人账号和密码，实例地址与团队配置由启动者提供。服务端校验禅道身份后建立单一内存会话。各账号沿用实例与账号隔离的存储。页面数据来自已有查询、进展、排期及管理服务。 |
| 规则 | 守住 11 §3 不变量。登录、切换角色与调用工具均由服务端校验。业务数据作为文本展示，读取缺口和推测必须可见。写入复用操作执行器，仅确认本次会话以该职责预览的计划，保留 W2 等待和回读。 |
| 能力 | 新增 `bzt web` 本地入口。按职责展示工作、提需、需求流转、拆解排期、风险与计划/发布/承诺/迭代视图。通过配置编辑器维护同一份角色表。复用已有工具契约，无新增 MCP 工具或禅道端点。 |
| 验收 | WEB-01 检查八个角色、兼任、既有 QA_LEAD、账号无映射。WEB-02 检查登录失败、退出、会话替换及服务端拒绝越权。WEB-03 检查按职责查阅真实服务结果和缺口。WEB-04 检查表单预览、用户确认、服务端 W2 护栏及操作回执。WEB-05 检查 CLI、本机监听、同源请求与打包资源。 |

## 页面与操作范围

| 职责 | 主要入口 |
| --- | --- |
| 业务反馈者 FB | 我提出的事项、提需求、进展回执 |
| 设计主管 DM | 待接收与评审、需求台账、提需、指派、移交和设计拆解 |
| 设计人员 DS | 我维护的需求、验收交付、提需、移交与设计拆解 |
| 研发主管 RM | 待接收与未就绪、本月研发队列、排期、拆解、指派、挪月、关闭 |
| 研发人员 RD | 本人待办与临期任务、研发范围与验收条件、补录需求 |
| 测试人员 QA | 可开测、即将开测、相关需求与只读版本发布门禁（US-QA-03） |
| 产品管理 PM | 月度计划、版本发布门禁、承诺与风险、门禁例外预览 |
| 项目管理 PJ | 迭代、月度承诺、团队排期与风险巡检 |

HTTP 适配层按已登录会话和所选职责校验操作。启动参数不接收监听主机，静态资源固定在包内。导出配置及替换团队文件沿用 CR-001。正式禅道写入和试点验收由业务方在选定对象上执行。

## 2026-11-25 验证

Edge 连接本机门户和隔离的假禅道，分别进入八种职责的首页。设计主管从表单预览 W2 需求，经确认后读回成功；刷新、切回同一职责再打开表单，仍可核对同一编号，假禅道共收到一次创建。撤销角色后重新加载，业务导航收起；在一个标签页退出，另一页也回到登录。390 像素宽度的回执页可以正常阅读。

真实禅道验证使用现有本人账号，已通过登录、身份回读、无映射提示和退出。现场八角色业务验收需先在团队配置中填入实际账号。前端试点和 #29 实际写入流程复验见 10 §3–4。
