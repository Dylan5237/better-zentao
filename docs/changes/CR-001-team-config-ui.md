# CR-001 离线可视化团队配置页生成器

分类为 11 §4 的环境差异。项目管理通过本地页面维护 08 定义的团队配置。

## 六步需求卡片

| 步骤 | 说明 |
| --- | --- |
| ① 意图 | 项目管理在接入产品、调整模块职责或变更成员时，使用可搜索的产品、模块和人员目录维护团队配置，并审阅将要保存的 JSON。 |
| ② 口径 | 沿用 08 §3、§5 与 `teamConfigSchema`。`modules` 按产品 ID 和模块 ID 定位。每个主管字段独立继承产品默认。CFG-06 跳过禁用产品和只探查的 #29。已确认空模块列表有效，缺清单单独提示。未编辑配置段原样保留。 |
| ③ 数据 | 复用 06 中的产品列表、产品 `moduleOptionMenu` 和 v2 全量用户 API。一级模块取单段菜单路径，排除 ID 0。人员使用未删除且有账号的目录记录，字段限账号、姓名、拼音、部门。也可传入同结构离线快照。 |
| ④ 规则 | 沿用 CFG-06、CFG-10、SEC-01、SEC-02 和 S01。页面另检查模块的团队引用。浏览器拒绝疑似凭据、连接地址及错误的编辑区结构。保留配置文件的合法内容，遇到初始数据不安全则停止生成。 |
| ⑤ 能力 | 生成器在有只读客户端时读取目录，在离线模式使用传入的快照或本地配置。产物是指定路径上的自包含 HTML 文件，打开后可编辑、导入、预览、复制和下载 `team.local.json`。无 HTTP 服务、外部脚本或新增依赖。CLI 子命令由后续集成接线，本次不新增 MCP 工具，沿用 20 个工具的上限。凭据、Webhook 和禅道连接地址不进入页面。 |
| ⑥ 验收 | CR-001-AC-1 验证五页签、中文目录、导入导出与非编辑字段保留。CR-001-AC-2 按 09 S01 / AC-82 验证凭据过滤、DTO 投影与脚本安全。CR-001-AC-3 验证读失败与分页截断的缺口、离线模式和目录创建。 |

## 不变量逐项核对

| 编号 | 本次约束 |
| --- | --- |
| INV-01 | 禅道目录是读取时的事实来源。HTML 携带目录快照，导出文件只承载团队配置。 |
| INV-02 | 复用端点 DTO，并将目录再次投影为页面所需字段。 |
| INV-03 | 无禅道对象创建。 |
| INV-04 | 无禅道写入，也不改变确认级别。 |
| INV-05 | 不新增或代填业务事实字段。 |
| INV-06 | 不调用写入能力，不生成操作计划。 |
| INV-07 | 不改动任务或需求统计。 |
| INV-08 | 读取失败、分页截断和离线缺失目录用 `gaps` 和 `completeness` 表达。 |
| INV-09 | 只显示配置和已读取目录。缺清单显示待核对。 |
| INV-10 | 产品 `state` 只编辑配置枚举，不推断禅道记录状态或业务进展。 |
| INV-11 | 不统计工作量或个人绩效。 |
| INV-12 | 目录文字与用户配置作为不可信数据，嵌入前转义，界面通过 DOM 文本节点显示。 |
| INV-13 | I/O 在服务层，渲染与浏览器表单在 CLI 适配层。 |

## 集成

调用方提供 `renderTeamConfigEditorHtml` 作为 `generateConfigEditorPage` 的渲染函数，并传入输出路径。线上目录读取需要注入现有只读客户端。配置来自传入对象、指定团队文件或内置默认值，团队文件读取跳过个人配置。调用方可传入环境配置用于文件定位和敏感值核对，生成器只序列化页面模型。浏览器中的实时校验覆盖编辑区和上述规则，完整配置校验仍以 `bzt doctor` 为准。
